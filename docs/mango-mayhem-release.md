# Mango Mayhem: A Very Sticky Situation

## Scope

An original, single-player, colourful 2D manga platform game. Six authored courses have different layouts, helper interactions, boss patterns and backgrounds. Guannan is the playable character throughout. Stephen appears in Dublin; Zachary in London; Mulan the dog at the Taj Mahal; Gaby in Sichuan; Sara in Neimenggu; and fictional older parent characters in Liaoning. No supplied photograph is served, stored in public assets or used as a texture.

The title screen opens first, including old `play=1` queries. Five hearts, checkpoints and unlimited retries. No timer, leaderboard, voice recording, multiplayer, adverts, analytics SDK or paid content. Mangos have stable unique IDs: 120 per location, 720 total. Collected mango outlines can be seen on replay without double counting. Each first level clear unlocks a costume regardless of collection total. The wardrobe contains seven articulated outfits, not recolours. Accessories unlock at 120, 240 and 360 mangos.

## Controls and comfort

Keyboard: arrows or A/D move, Space/W/up jumps, X/Shift spins, Escape pauses. Hold jump for a larger hop. Bindings can be changed. Standard gamepad: stick/D-pad moves, A/cross jumps, X/square spins, Start pauses. Menu navigation uses the stick/D-pad, A to select and B to go back. Jump/spin buttons can be reassigned. Landscape touch controls accept simultaneous direction and jump pointers, with release/cancel handling.

Background music and event effects are original synthesized compositions, with separate sliders. Audio waits for a user gesture. Reduced motion removes shake and limits particles; an extra-help setting adds safety platforms and longer boss openings. Losing focus, hiding the document or disconnecting the controller pauses the game. Resume is deliberate. Mobile landscape keeps a full 16:9 field visible. Fullscreen is offered only through the browser API and failures remain usable.

## Profiles and privacy

Device profiles do not require sign-in. The existing Duck & Bear account can link up to six cloud profiles. No child email or new public user registration is added. APIs use the original authenticated session and active-account check. Every SQL operation is scoped to the signed-in owner, including updates and deletes. Revisions use compare-and-swap, and stale saves return an owner-only current snapshot. Mango sets merge by union; cleared levels and checkpoint progress are monotonic. Deleted profiles cannot be recreated by stale saves. A failed save stays dirty locally and never displays a false cloud success. A change of signed-in owner does not send the previous account's queue into the next account.

Writes require same-origin JSON, a streamed 32 KiB body limit, strict field and save validation, and durable per-owner limits (60 writes/minute, 10 creates/hour). All save API responses are `no-store`. The service worker continues excluding all API, private media and game routes. Private orders, points, memories, accounts and racing storage are not altered. The additive migration creates only `mango_profiles`, `mango_rate_limits` and their index. Production applies migrations before deploying the new code.

The public `/api/mango/health` exposes only game name/version and whether the two save tables exist. It returns no users, profiles, counts of player records, account data or secrets.

## Integration

`/games/` lists both games. `/games/mango-mayhem/` opens the new game. A new card appears on the public homepage and existing account Games tab. Existing racing URLs, setup, seven-car cap and online rooms are preserved. Assets have an explicit allowlist: a missing module returns a true 404, not the site's single-page-app fallback. Runtime code and artwork are self-hosted. No additional production dependency or service is required.

Run `scripts/integrate-mango.py` against the existing checkout for narrow, repeat-safe edits. It refuses unexpected anchors rather than overwriting an unfamiliar file. The source release fingerprint is generated by `node scripts/mango-build-release.mjs` and validated by `node scripts/mango-check.mjs`.

## Verification

`node --test tests/mango-*.test.mjs` exercises movement, collisions, ramps, one-way platforms, movers, health, pickups, progress, all bosses, input adapters, sprites, saves, ownership, revision conflicts and full input-driven courses. `tests/mango-browser.py` completes all six levels through normal input handlers and menus, checks sequential unlocks, outfits, reloads, touch and controller adapters, and saves screenshots. It changes clock progression but has no state-setting, teleport, invincibility or auto-win API. Its diagnostics return structured clones and cannot change the running game.

`tests/mango-auth.py` exercises the existing Worker authentication with real PBKDF2 credentials and temporary identities against local Wrangler. `tests/mango-cloud-browser.py` checks two isolated browser contexts and an actual browser network outage. The synthetic identities are generated under `.wrangler` and are never used on production or committed. Existing racing browser and room suites run alongside the new checks. Live acceptance verifies the published source hashes and schema readiness before browser tests.

Screenshots and reports are retained as private GitHub Actions artifacts for seven days. Test records, rather than this document, determine release status. Headless Chromium, emulated touch and injected standard-controller readings do not certify every physical handset, controller model or native fullscreen implementation. Such hardware has not been physically tested here.
