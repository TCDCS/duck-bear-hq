# Illustrated Duck & Bear HQ — approved implementation scope

The user approved the sectioned design in the conversation and explicitly asked for implementation in this session. Keep existing games, account history and dated menu archives. Use the existing Cloudflare Worker, D1 database and private R2 bucket; no new framework or hosting provider. Use a colourful, illustrated paper/notebook design and real path-based links throughout.

## Privacy and identity
Only the original setup administrator and member are the initial household pair. Resolve their IDs from the original `setup.complete` audit event, not usernames, roles or email addresses. If that evidence is unavailable, fail closed and offer the existing first administrator an explicit pair setup screen. Newly invited users receive zero private-section permissions until the owner assigns them. Read/contribute/edit/manage and export are separate server-authorised capabilities. Pair-only reviews and shared private notes remain inaccessible to invited family contributors. Every private asset, API, history, search and export request must check current permissions. Disable/delete revokes sessions. Account deletion removes personal access/details, preserves shared contributions and never deletes the last owner. Existing legacy account APIs and media are pair-only when reached through the new wrapper.

## Structure
Public home, games, menus, shop, about and info. Signed-in Our Space; Menus (planner, ideas, recipes, reviews, shopping, archive); Family Tree (tree, people, timeline, changes, access); Scrapbook (albums, memories, calendar, favourites, drafts); Plans (calendar, ideas, polls, bucket list, completed); image library; Settings (profile, email, security, devices, notifications, appearance, language, data); Admin (users, invitations, permissions, appearance, backups, history). Every subsection and record has a real URL, breadcrumbs and back/refresh support. Use popups only for short actions.

## Features
Typed, versioned D1 records instead of overwriteable shared JSON. Preserve legacy R2 data during migration. Weekly draft planning, new-week copy, ideas, votes, recipe notes, editable shopping entries, immutable published weekly snapshots and serving-specific private reviews. Tree relationships support birth/adoptive/step parents, partners and other relationships, optional/approximate dates, multilingual names, branch focus, list fallback and proposed corrections. Scrapbook albums and memories support layouts, captions, image order/crops, comments, favourites, original image preservation and on-this-day. Plans, polls, bucket list, surprise picker and convert-to-memory connect to the content. In-app notification/activity views only display authorised records and can be disabled. No automatic public publication or external sensitive notifications.

## Media and accounts
Keep the four supplied images private. Never commit plaintext private pictures into the public repository. Import to private R2 only through authorised access; if no authenticated upload session is available, deliver an import bundle and record that limitation. Photo selection, upload, crop and cover replacement keep originals. Invite-only accounts, current-password email registration, verified email flow, single-use reset tokens, rate limits, same-origin checks and session controls. Email sending requires a configured/verified sender; never report emails as delivered on an unconfigured system. Retain a clearly labelled administrator-assisted recovery path.
